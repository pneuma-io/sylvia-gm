# INTRUSION

**At a glance:** Use a real access route to change one declared network state; authorized activity is automatic, while uncertain hostile access is one CHECK against the specific barrier being attacked.

> [!note]- Full rules
> - Every action requires a real route and its prerequisites: physical LOCAL ACCESS, a NODE, a LINK, a valid session or CREDENTIAL, an exposed service, a GATEWAY, or another authored path. Skill never invents connectivity or device capability.
> - Following an open LINK through already controlled NODES is automatic. Using a REMOTE FUNCTION permitted by current PRIVILEGE is automatic, though the function still consumes its actual operational AP/time.
> - A defended access boundary, authentication bypass, hostile PIVOT, hidden-topology DISCOVER attempt, or ESCALATE attempt calls for a CHECK only when the outcome is uncertain and matters.
> - Security belongs to the specific access route or barrier being attacked. A NODE does not have one generic cyber-armor or cyber-HP score that replaces its architecture.
> - Before committing, declare one concrete result such as establishing access, revealing hidden topology, obtaining a stated PRIVILEGE, operating a function, extracting data, or installing a FOOTHOLD. Spend the required AP/resources and make one CHECK. Success changes that declared state when the route and capability support it.
> - Failure spends the attempted AP/resources but does not invent device damage, revoke unrelated access, or automatically cause DETECTION. The action's real visibility, MONITORING, and evidence determine defender awareness; a successful action can also be noisy.
> - The same attempt may be repeated while its route and target remain available. Each attempt pays its normal AP and detection exposure. A retry becomes unavailable only when real state changes, such as session termination, an authored account lock, credential revocation, segment isolation, route loss, shutdown, or destruction.
> - Automated defenses act only through authored triggers. Human defensive actions consume real time/AP. DETECTION permits responses; it does not automatically eject the intruder.
>
> Discovered topology remains useful knowledge but can become outdated when the authored network changes. Successfully stolen data remains stolen. CREDENTIALS persist until their real scope or validity changes. Ordinary live sessions and temporary PRIVILEGE end when their route/session ends; only an explicit FOOTHOLD provides persistent re-entry.
>
> Exact AP, DIFFICULTY, action visibility, monitoring, persistence, and specialty values are balance/reference parameters.
