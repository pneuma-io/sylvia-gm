# LOCAL HACKER

**At a glance:** HACKER specialty that takes deep control of one directly or locally accessible NODE rather than traversing an entire NETWORK.

> [!note]- Full rules
> - The shared HACKER loop remains GET IN → GO DEEPER → STAY QUIET → DO IT FAST.
> - LOCAL HACKER requires a valid direct/local access path and preserves physical hardware, software, permissions, and security constraints.
> - HACKER's TACTICAL INTRUSION baseline already reduces AP/time for intrusion actions once a valid access route exists. LOCAL HACKER Entry must therefore add something beyond merely making GET IN / GO DEEPER faster.
> - Exact AP, security-state, difficulty, and persistence values remain balance parameters.
>
> **ENTRY — SERVICE ACCESS:** The initial GET IN attempt made through genuine direct/local access gains improved reliability by reducing its DIFFICULTY. This changes reliability rather than repeating HACKER's AP/time benefit. It does not create an interface, bypass missing hardware, grant privilege beyond the compromised route, or provide access to another NODE.
>
> **TIER 1 — Understand the box**
> - **DIAGNOSTIC VIEW:** After successfully accessing a NODE locally, automatically obtain a broader snapshot of its observable operating state without separate actions for each element: active functions, connected peripherals, current configuration, active users/sessions, obvious faults, and exposed local controls where the NODE knows them. Information the NODE does not possess remains unavailable.
> - **LOCAL ESCALATION:** GO DEEPER attempts made through direct/local access gain improved effectiveness. This improves privilege/control escalation on the current NODE and does not provide access to other NODES.
> - **QUIET CONSOLE:** Lower the HACKING VISIBILITY of actions performed through genuine direct/local access. The action can still be detected, and physical evidence at the interface still exists.
>
> **TIER 2 — Take control**
> - **MULTI-FUNCTION ACCESS:** After successfully gaining deep control of a NODE, manipulating a second distinct function on that same NODE costs less AP than establishing control over it from scratch, provided both are genuinely functions of that NODE.
> - **SNAPSHOT:** Capture the NODE's currently accessible configuration and state as one HACKING action. Later comparing the live NODE with that snapshot or restoring supported captured values costs less AP. The snapshot contains only fields the current access can read, restoration changes only fields the NODE permits the current control to write, and storage is still required.
> - **LOCAL LOCKOUT:** After taking deep local control, harden that NODE against remote configuration/control attempts. Those attempts face increased difficulty until the lockout is removed, reset, reconfigured, or control is defeated. This does not disconnect the NODE unless that is actually commanded.
>
> **TIER 3 — Make the change stick**
> - **PERSISTENT OVERRIDE:** Choose one configuration or control change made through deep local access. If the NODE supports persistent configuration, the change survives session ending and ordinary restart/reconnection. Proper reset, administrator intervention, replacement configuration, or destruction can still remove it.
> - **INTERLOCK BYPASS:** When a NODE contains a software-enforced operating limit or safety interlock, deep local control can temporarily bypass it. Hardware limits remain; unsafe operation may produce heat, wear, failure, or physical damage.
> - **RAPID RECONFIGURE:** Once deep control is established, switching the NODE between two configurations already established by the hacker costs substantially less AP/time than rebuilding either configuration.
>
> **TIER 4 — Own the box**
> - **HARD LOCKOUT:** With deep control, choose one lockout action the NODE has authority to perform: **INVALIDATE SESSIONS** ends its active remote sessions, or **REVOKE ACCESS METHOD** revokes one selected currently valid remote-access method. The choices do not stack. Affected users must establish access again through a method that remains valid.
> - **SCRIPTED ROUTINE:** Install one simple conditional routine using functions the NODE already controls, such as when this sensor triggers, close that door. It continues without active attention and cannot invent sensors, actuators, permissions, or capabilities.
> - **LOCAL COUNTER-INTRUSION:** Gain a PREP ACTION while maintaining deep local control. Declare a remote-control or intrusion condition affecting that NODE; if it occurs, immediately attempt a HACKING response before it fully resolves. The incoming action must actually pass through or affect the controlled NODE.
>
> **TIER 5 KEYSTONE — ROOT ON THE BOX**
> - Once deep local control is achieved, successive actions that inspect, reconfigure, manipulate functions, establish persistence, or defend control require dramatically less tactical time. The NODE has one PERSISTENT OVERRIDE slot and one SCRIPTED ROUTINE slot for this hacker; both can remain active together, and replacing one does not replace the other. Each slot retains its own ordinary trigger, capability, persistence, and remediation limits. The keystone still controls one machine only and cannot cross an absent LINK, exceed hardware, prevent physical destruction, or make remediation impossible.
