# FIELD ENGINEER

**At a glance:** TECH specialty that deploys, repairs, modifies, reinforces, and sustains physical technical systems and battlefield infrastructure.

> [!note]- Full rules
> - FIELD ENGINEER is physical technical work, not HACKING and not BREAKER-style entry-point destruction.
> - Tools, materials, access, power, components, and physical plausibility remain required.
> - TECH's SYSTEMS HANDLING baseline already improves intended operation and deployment of physical technical equipment. FIELD ENGINEER must add ENGINEERING-specific capability beyond merely repeating that baseline.
> - Exact repair amounts, AP, durability, overdrive, and deployable values remain balance parameters.
>
> **ENTRY — FIELD WORK**
> - Extend TECH's tactical-time efficiency into ENGINEERING work that SYSTEMS HANDLING does not already cover: repairing, physically reconfiguring, and modifying compatible technical systems costs less AP/time than it does for a baseline TECH. The reference task is physically reorienting an already deployed FIELD SENSOR / RELAY NODE: it costs a baseline TECH 3 AP and a FIELD ENGINEER 2 AP. This changes only the declared physical configuration. It grants no new sensor power, range, privilege, software function, or other capability. Ordinary deployment alone is not further discounted by this Entry unless another FIELD ENGINEER ability says so. Appropriate tools, materials, access, and technical capability are still required.
>
> **TIER 1 — Keep things running**
> - **FIELD REPAIR:** Restore more lost functionality/HP to a damaged repairable device, drone, deployable, or other mechanical/electrical system for the same repair time and materials. Destroyed components may still require replacement.
> - **RAPID DEPLOYMENT:** Placing and activating a carried deployable technical device costs an additional AP step less beyond the ordinary TECH SYSTEMS HANDLING benefit, to a minimum final cost of 1 AP. The device must already exist in inventory.
> - **PATCH JOB:** Make a temporary repair faster than a full repair and restore one named function the damaged system could ordinarily perform. Choose one liability when applying the patch: **FRAGILE** gives the restored function limited durability and the next qualifying failure disables it, or **ONE USE** keeps the function only through one meaningful use. Proper repair replaces the patch; a patch cannot restore a destroyed or missing component.
>
> **TIER 2 — Improve the equipment**
> - **FIELD MODIFICATION:** With tools and suitable components, temporarily alter exactly one defined physical characteristic of a compatible device or deployable: **SENSOR ORIENTATION**, **MOUNTING**, **STABILITY**, **POWER ROUTING**, or **OPERATING MODE**. State the physical before-and-after configuration and one directly linked tradeoff when the modification is made. The change must be physically plausible, cannot exceed the installed components' capabilities, and ends when removed, replaced, or properly rebuilt.
> - **HARDEN SYSTEM:** When deploying or servicing a device, reinforce it against physical damage or environmental exposure, increasing effective durability. This does not make delicate electronics bulletproof.
> - **POWER BUDGET:** Redistribute remaining endurance between physically connected, electrically compatible devices or subsystems. Power is conserved: extending one system's operating duration consumes the donor's available power and may shut the donor down. Borrowed endurance lasts only while the power-capable connection remains intact. POWER BUDGET does not increase output, sensor reach, or other performance; pushing output beyond its safe envelope belongs to OVERDRIVE. Each compatible equipment pair defines its own exchange quantity, and exact rerouting AP/time remains a balance parameter.
>
> **TIER 3 — Shape the position**
> - **EMPLACE:** A deployable weapon, sensor, barrier mechanism, or similar device deliberately emplaced by the engineer gains improved stability, durability, or operating effectiveness compared with merely setting it down. Emplacement costs setup time and makes relocation slower.
> - **FIELD SENSOR:** Deploy and configure a carried sensor to establish a persistent monitored area more efficiently. It detects only what its actual sensor type can detect.
> - **TECHNICAL OBSTACLE:** Using appropriate materials and equipment, rapidly establish one temporary denial device across a limited area. Choose **OBSTACLE** to add movement AP to each affected grid cell crossed, or **HAZARD** to install a named device or material whose existing trigger and effect resolve normally. HAZARD creates no generic damage or condition of its own. Both choices must be represented by actual placed hardware or material, and removing or bypassing that hardware ends the effect.
>
> **TIER 4 — Sustain the position**
> - **HOT REPAIR:** Repair a friendly device while it remains operational. Repair effectiveness is lower or riskier than shutting it down for proper work, but the system does not have to leave service. Physically inaccessible moving components remain inaccessible.
> - **REDUNDANT SYSTEM:** When preparing an emplaced technical device, name one important function and add a real backup component or path for it. The first qualifying component failure switches that named function to the backup instead of disabling it. The backup operates with an effectiveness penalty until the failed component is repaired. Other functions and later failures resolve normally.
> - **OVERDRIVE:** Temporarily push a compatible device beyond its ordinary safe performance envelope to improve one output such as movement, sensor performance, rate of operation, or power. Afterwards it accumulates a physically appropriate cost such as wear, damage, heat, or depleted power.
>
> **TIER 5 KEYSTONE — FIELD WORKSHOP**
> - Given suitable tools, parts, and a defensible working position, deployed systems can be emplaced faster, repaired while operational, temporarily modified, reinforced, overdriven, and restored from damage with much less downtime. Nothing is manufactured from nothing: parts, power, replacement components, and physical access remain real requirements.
