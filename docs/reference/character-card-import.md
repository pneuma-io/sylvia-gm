# Character sources and external cards

Universal character cards remain unbound. Native General Profile is the implementation contract. The Builder definition `character_profile` describes unchanged native v1. `character_profile_v2` describes rich optional sections: identity/aliases, description/personality/appearance/voice/history, relationships, scenario/portrayal, greetings/ordered alternatives/group greetings, dialogue examples, addressable lore, creator/source notes/tags/revision/languages, inert asset references and bounded typed foreign settings. Missing, empty and disabled values remain distinct. No facts are inferred from v1 prose and no old source, adaptation or campaign is migrated.

Use Builder workspace author/edit tools, check and publish with the observed file version. Open a full saved source or read an exact section/entry with `read_character_profile_section`. Large sections over 64 KiB need a full workspace copy or one entry. Profile JSON/canonical bytes are limited to 256 KiB, unique members, finite numbers and nesting 32. Every object section has declared fields. Array and text limits are in the definition; excesses reject, never truncate.

## Supported external formats

Flat Character Card V1, Character Card V2 2.0 (`chara_card_v2`), and Character Card V3 3.0 (`chara_card_v3`) are accepted as UTF-8 JSON or PNG tEXt metadata (V1/V2 `chara`, V3 `ccv3`). When both are present V3 is selected and V2 is retained in the original. Duplicate metadata is ambiguous and rejects. CHARX/ZIP, APNG-specific asset extraction, compressed/iTXt card metadata and arbitrary containers are unsupported. A regular card PNG may include other inert chunks, which remain in the retained original.

Specifications: [V1](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v1.md), [V2](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md), [V3](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md).

Description/personality map to biography; scenario to portrayal; first_mes and ordered alternatives to greetings; mes_example to one addressable dialogue example retaining its exact text; character_book entries to addressable lore retaining supplied IDs, order, enabled flags, keys and metadata; creator/notes/tags/revisions/languages/source links to metadata. Empty optional areas are retained when supplied. Name padding is explicitly transformed, with the original retained. Unknown fields, prompt overrides, settings, extension data and full asset descriptors are bounded typed JSON marked preserved_only. The preview lists imported, transformed, preserved-only, unsupported and omitted content before saving. The original bytes and their SHA-256 are stored immutably and revalidated on reads.

Settings → Packages → Import Character Card opens the local file picker, shows the conversion preview, then Save Universal character card confirms retention and validation. The preview uses the character's name with Universal character card and the status Needs ruleset adaptations. Detailed conversion information is available in expandable details; material unsupported behavior remains visible before saving. Builder can independently retrieve `get_character_card_import_contract`, preview a guarded workspace card and import its exact observed version. These operations never make a source playable. Choose the saved Universal character card in the companion picker, explicitly adapt it to the selected Setting and its contained Ruleset, and pass existing character checks/publication. Launch adaptations must target the actual 117-spell SRD Lite package; importing alone does not prove that adaptation. No mechanical power is inferred from lore.

Source limit is 16 MiB, embedded/standalone JSON 256 KiB, nesting 32, PNG 4096 chunks, dimensions 8192 per side and 16,777,216 pixels. No image decompression, script execution, regex/lore activation, macro expansion, external asset fetch or foreign provider/system-policy change occurs. Remote URLs remain references; local/credential-bearing or traversal asset paths reject. Inline/embedded assets identify retained original content without decoding it. No external export/round-trip is promised.

Scenarios, examples and greetings are reference material and do not become played campaign history. Foreign instructions remain untrusted data even when a Builder reads a section. Original-world history is authored source history and must be reconciled explicitly during target adaptation.

Confirmed desktop imports release their temporary preview slot only after the retained original and saved profile have been verified. Repeating confirmation checks those saved bytes and returns the same profile. Failed saves and unsafe or changed entries retain their pending slot. Older completed staging files are retired on the next preview only when the same checks pass. At most 64 genuinely pending previews are admitted; the existing 256-profile library limit remains in force. Retirement removes only a temporary duplicate, preserving the immutable original, saved profile and prior adaptations.

Unknown card data members remain in inert `foreign_configuration.settings`. Unknown V2/V3 root members are grouped under `outer_extensions`; if that name belongs to a data member, the importer uses the first unused `outer_extensions_root`, `outer_extensions_root_1`, and so on. Both members retain their exact values. The conversion preview identifies data and root source fields and discloses the replacement grouping key. This grouping changes the native representation only; foreign controls stay unsupported and source bytes remain intact.

Previously saved collision-affected profiles are preserved as they were. Re-preview and explicitly import the retained original to create a corrected profile; this repair does not silently migrate an existing profile or its adaptations.
