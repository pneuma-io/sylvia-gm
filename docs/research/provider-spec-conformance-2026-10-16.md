# Provider specification conformance — 16 October 2026

This successor preserves Build2082 and repairs the existing provider contracts. The selected verification criterion is implementation against official specifications plus meaningful synthetic verification where subscriptions are unavailable. A new live account or subscription is not a prerequisite for this work. Existing genuine Sol evidence retains its original source/runtime bounds; native desktop and installed acceptance remain separate.

The source roster contains **25 presets and five transports**. Eighteen hosted presets are covered in the [hosted specification audit](provider-spec-2026-10-16/OFFICIAL-HOSTED-PROVIDER-SPECS.md), with its [dated source/claim index](provider-spec-2026-10-16/OFFICIAL-HOSTED-PROVIDER-CLAIMS.json). The other seven are covered in the [local/custom/subscription matrix](provider-spec-2026-10-16/LOCAL-CUSTOM-SUBSCRIPTION.md). The [extracted preset roster](provider-spec-2026-10-16/IMPLEMENTED-PRESETS.json) is source-derived. Discovery and inference are separate paths; the historical four-transport statement is superseded.

Repairs stay within the roster. OpenCode's existing discovery bases remain unchanged while inference resolves the selected OpenAI/Anthropic/Google family. Saved custom endpoints and explicit local ports are preserved. New llama.cpp profiles use its current documented default port. Ollama installed-model metadata no longer depends on the model being present in its running list; declared limits do not become fabricated runtime capacity.

Private native fields use the existing separate provider-record store and provider/model binding. They are attached after context selection for the selected request; they do not enter ordinary campaign history. Missing required native data produces the existing actionable restore/export-with-Thinking error. Full Responses output is validated against saved tool IDs, names and arguments before replay. Exact scalar keys are retained for Together, Cerebras and documented equivalents; unspecified Groq/Featherless scalar replay is not enabled.

Failure handling does not accept partial tools as completed work. Stream cancellation closes the actual SDK response without resubmitting generation. Reported failed-terminal usage reaches the error hook and usage tracker once; absence remains unknown. HTTP retryable errors keep server Retry-After metadata, including 503. The request loop normalizes SDK connection failures before configured nonstream retry; started streams are never automatically replayed.

Official sources and model-specific qualifications are dated in the linked matrices. The launch-delivery report records exact final source identity, test results, initial red reproductions and guarded pre/post hashes. Test counts are evidence of selected contracts, not an exhaustive certification of every model, server deployment, entitlement or provider policy.

Known boundaries: native Gemini automatic token hops; Claude server-tool pause continuation; unspecified gateway encrypted/include/strict/session-header details; incomplete provider documentation listed in the hosted audit; actual custom server policies; unrun live behaviour outside retained Sol evidence. Refusals and unknown stops are explicit failures, not ordinary success or automatic bypass. New UI screenshots are unnecessary for this adapter-only change; existing rendered setup evidence remains historical proof. No compiled successor, native input, installed launch, publication or legal adoption is implied by source tests.
