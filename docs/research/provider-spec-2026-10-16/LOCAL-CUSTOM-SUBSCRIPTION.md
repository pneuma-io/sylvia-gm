# Local, custom and subscription provider contracts

Official sources checked 16 October 2026. This is a specification audit of Sylvia's existing routes. It does not claim a locally running model, downloaded weights, server deployment, account entitlement or new live inference.

| Preset | Selected wire contract | Endpoint/authentication and prerequisites | Evidence and limits |
|---|---|---|---|
| LM Studio | Chat Completions | Configurable base, preset `http://127.0.0.1:1234/v1`; `/models` and `/chat/completions`; optional server authentication uses Bearer. A suitable loaded/available model must support its selected tools and chat template. | Official [compatibility reference](https://lmstudio.ai/docs/developer/openai-compat), [tool calling](https://lmstudio.ai/docs/developer/openai-compat/tools), [authentication](https://lmstudio.ai/docs/developer/core/authentication). Synthetic SDK requests and discovery/capacity tests; no server launch. The documentation's 1234 examples assume that port. |
| Ollama | Chat Completions | `http://127.0.0.1:11434/v1`; SDK's nonsecret dummy API key is ignored by a default local server. Tools, streaming usage and `max_tokens` are documented. `/api/ps` reports running context; `/api/show` supplies installed-model metadata independently of running state. | Official [OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility), [running models](https://docs.ollama.com/api/ps), [show model](https://github.com/ollama/ollama/blob/main/docs/api.md#show-model-information). Declared model maximum remains distinct from actual runtime capacity; no model load occurs during discovery. Ollama Responses is stateless and does not promise previous_response_id; Sylvia's preset stays Chat. |
| llama.cpp | Chat Completions | New-profile preset `http://127.0.0.1:9931/v1`, matching current server default; explicit saved ports remain intact. API keys are optional; selected key uses Bearer. Tool parsing requires a suitable model/template and server configuration. | Official [server reference](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/server/README.md), including `--port` default 9931, optional `--api-key`, Chat routes, function calling and OpenAI-shaped errors. No installation, model load or global setting changes. |
| vLLM | Chat Completions | `http://127.0.0.1:8000/v1`; optional `--api-key` enables Bearer authentication. Model needs a chat template; tool parser/configuration and model determine actual tool behaviour. | Official [OpenAI-compatible server](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/) and [tool calling](https://docs.vllm.ai/en/latest/features/tool_calling/). Standard nested functions, indexed stream deltas, linked results; no assertion that every hosted model supports tools or parallel calls. |
| LocalAI | Chat Completions | Configurable preset `http://127.0.0.1:8080/v1`; official source registers `/v1/models` and `/v1/chat/completions`. Deployment controls authentication and backend capabilities. | Official [route source](https://raw.githubusercontent.com/mudler/LocalAI/master/core/http/routes/openai.go), [Chat handler](https://raw.githubusercontent.com/mudler/LocalAI/master/core/http/endpoints/openai/chat.go), [project guide](https://github.com/mudler/LocalAI). Handler emits standard SSE data and DONE, usage trailers, linked calls and explicit error envelopes. Several localai.io feature pages returned only “Moved”; authentication/model-specific guarantees are qualified rather than invented. |
| Custom endpoint | Explicit selected supported transport | Preserve the exact user URL and selected protocol. No upstream catalogue URL becomes a credential destination. Custom header values remain private; no universal service capability can be inferred. | Transport-level SDK fixtures establish Sylvia's request shape. Actual custom server policy is an external contract; it is not certified by another provider's compatibility claim. OpenCode normalization only rewrites the exact known HTTPS host and documented inference bases. |
| ChatGPT subscription | Codex App Server | Isolated owner-managed runtime home, stdio JSON-RPC, initialize/initialized handshake, models, thread/start, history injection, dynamic tools, turn notifications and interruption. Sylvia never reads the runtime's credential files. | Official [App Server protocol](https://learn.chatgpt.com/docs/app-server), version-specific generated schemas where retained, existing runtime/adapter contracts and unchanged genuine Sol evidence. Shared Responses function conversion retains flat tools and explicit strict flags; it does not inject direct-API store/include options into Codex. No new live Sol call is required by the revised provider criterion. |

All HTTP presets use a real installed SDK or native HTTP adapter with `httpx.MockTransport` fixtures for representative streaming/tool/result paths. These tests capture final HTTP methods, URLs, headers and JSON, not only mocked adapter return values. The automatic-setup matrix covers rich, sparse and absent model limits, save/reopen, profile aliases and switching. Default model selection and optional numeric overrides remain separate from discovered metadata.

The common wire boundary preserves multiple tool deltas and validates identities; cancellation closes the owned stream and does not resubmit it. A finish label without Chat's documented DONE framing or a Responses/native stream without its terminal event is incomplete. Provider HTTP/status errors remain distinct from successful output; server Retry-After is a minimum wait rather than the application's exponential-backoff ceiling.

Local deployment versions, backend flags, available models and their genuine outputs remain untested. No such test was performed using a simulated result and labelled live.
